새 관측 0. 새 browser 0. 새 network 0. 새 AI 0.

> `dom.json`은 계속 structure/style/geometry의 primary truth이고,

## Source-of-Truth Policy

Task 13의 §25를 좁히지도 넓히지도 않았다.

```
dom.json       structure · computed style · geometry · visibility   ← primary truth
rendered.html  text node 값 · mixed-content 순서 · form action 유무
               + (Task 13.1) closed allowlist declarative attribute  ← supplemental
```

**동일 이름이 양쪽에 있으면 `dom.json`이 이긴다.** 코드에서 한 줄이다:

```ts
if (Object.hasOwn(raw, name)) continue; // item 5: the observed value wins
```

그리고 이 규칙이 **공허하지 않도록** 두 가지를 더 했다.

1. allowlist는 Observer의 `ATTR_WHITELIST`와 **disjoint임을 import 시점에 assert**한다.
   즉 오늘 이 branch는 도달 불가능하고, 실측 overwrite 후보도 **0건**이다.
2. 그럼에도 `dom.json`이 allowlist 이름을 들고 오는 경우를 **살려서 우선**하도록
   구현했다. 나중에 Task 03/04 whitelist가 넓어지면 그날 이 규칙이 실제로 발동한다 —
   그때 조용히 덮어쓰지 않는다. fixture가 `colspan="9"`(dom) vs `colspan="2"`(parsed)로
   이 경로를 직접 검사한다.

## Supplemental rendered.html Policy

`rendered.html`은 **primary structure truth로 승격되지 않았다.**

- element 개수·순서·부모 관계는 여전히 `dom.json`이 정한다
- parse tree는 이미 만들어 놓은 것을 재사용한다 (두 번째 parse 없음)
- 수확은 **walk 안에서 allowlist 필터를 통과한 이름만** 메모리에 담는다.
  `class`/`data-*`/`on*`/`action`은 *나중에 걸러지는 것이 아니라* 애초에 수집되지 않는다
- foreign content(SVG/MathML namespace)와 prefix 있는 attribute(`xlink:*`)는 수확 대상 밖.
  이 복구는 HTML semantics만 다룬다

저장은 sparse다. 148,373개 element 중 실제 복구가 있는 것은 324개뿐이라,
`Map<elementIndex, attrs>`로 들고 다닌다.

## Alignment Requirement

```
contentRecovery.status === "aligned"   → supplemental recovery 가능
contentRecovery.status === "fallback"  → supplemental recovery 0 (예외 없음)
```

`aligned`의 정의는 Task 13이 정한 그대로다: **element count + tag sequence + parent
relation 세 가지가 전부 일치.** fuzzy matching·text similarity·class·geometry·score는
이 Task에도 **하나도 없다**.

fallback viewport에서는 `compileAttributes()`에 supplemental map 자체를 넘기지 않는다.
"필터로 막는다"가 아니라 "존재하지 않는다"에 가깝게 만든 것이고, validator가
`fallback viewport에 recoveredAttributeNames가 있으면 위반`으로 잡는다.

## Explicit Denylist

수확 자체가 allowlist 기반이므로 아래는 **구조적으로 도달 불가능**하다. 그래도
`SUPPLEMENTAL_DENYLIST` + `SUPPLEMENTAL_DENIED_PREFIXES`를 두고 **import 시점에
검사**한다 — 미래에 누가 `formaction`을 목록에 추가하면 리뷰가 아니라 **import가
실패**한다.

금지: `class` `style` `id` `value` `src` `srcset` `sizes` `poster` `srcdoc` `href`
`action` `formaction` `method` `formmethod` `enctype` `formenctype` `target`
`formtarget` `nonce` `integrity` `crossorigin` `ping` `referrerpolicy` `http-equiv`
`content` `charset` `async` `defer` `nomodule`
금지 prefix: `data-` `on` `aria-` `xlink:` `xmlns`

정합성 검사 4종: 소문자 정규화 · denylist 미포함 · denied prefix 미포함 ·
**Observer `ATTR_WHITELIST`와 disjoint**.

## Boolean Attribute Semantics

`disabled` / `disabled=""` / `disabled="disabled"`는 **같은 사실 하나**다.
그래서 boolean kind는 값을 `""`로 정규화하고, 존재 자체를 기록한다.
SiteSpec의 표현은 기존 `attributes: Record<string,string>` 스키마 그대로다 —
새 필드도, 새 타입도 만들지 않았다.

validator가 이것을 **모든 노드에 대해** 강제한다:
allowlist boolean인데 값이 `""`가 아니면 위반. 채널과 무관한 불변식이다.

### `hidden`을 boolean에서 뺀 이유 (지시서 item 9와의 의도적 차이)

item 9는 `hidden`을 boolean 목록에 넣었다. 그런데 현행 HTML 스펙에서 `hidden`은
**enumerated attribute**이고 `hidden="until-found"`는 "find-in-page로 펼쳐질 수 있는
숨김"이라는 **다른 상태**다. presence로 접으면 그 구분이 사라진다 — item 10이 금지하는
"임의 normalization으로 의미를 바꾸는 것"에 정확히 해당한다.

그래서 `hidden`은 enumerated로 두고 값을 원형 보존한다. 실측 54건은 전부 `""`(bare
`hidden`)이라 결과는 동일하고, fixture에는 `hidden="until-found"`를 심어 접히지 않음을
검사한다.

## Recovery Provenance

```ts
ElementSpecNode {
  ...
  attributes: { colspan: "2", scope: "col" }
  recoveredAttributeNames?: ["colspan", "scope"]   // sorted, supplemental만
}
```

- 실제 복구가 있는 노드에만 **존재**한다. 빈 배열을 148,373개 element에 붙이지 않는다
- `dom.json`에서 온 attribute는 여기 들어가지 않는다
- validator: 이름이 allowlist에 있는가 · `attributes`에 실제로 있는가 · 정렬돼 있는가 ·
  빈 배열이 아닌가 · fallback viewport가 아닌가

viewport 단위 (`contentRecovery`):

```json
"supplementalAttributeCount": 132,
"supplementalElementCount": 132,
"supplementalAttributeNames": ["datetime", "hidden", "open", "scope"]
```

site 단위 (`stats`): 위 둘의 합 + `supplementalAttributeNameCounts`(per-name).
validator가 **site 합계 == viewport 합계 == 노드 실측**을 3중으로 대조한다.

provenance ledger에서 복구된 attribute는 `observedFactCount`에 들어간다 —
이 파이프라인이 저장해 둔 `rendered.html`에서 **그대로 읽은 값**이지 계산한 값이 아니다.

## Popover Attributes

실데이터 **0건**. 4개 사이트 어디에도 Native Popover API 마크업이 없다.

그래도 구현하고 fixture로 검증했다 — `popover` / `popovertarget` /

## Form / Security Boundary

Task 13의 경계를 **한 칸도 넓히지 않았다.**

- form `action` URL: IR 어디에도 없음. `sourceHasFormAction: boolean`만 유지
- `formaction` / `method` / `formmethod` / `enctype` / `formenctype`: allowlist 밖 + denylist
- password / hidden / file input `value`: item 8에 따라 **`value` 복구 자체가 없음**
- `javascript:` URL: `href`가 수확 대상이 아니므로 진입 경로 없음
- `nonce` / `integrity` / `crossorigin`: denylist

실사이트 검증: nextjs의 `<form action method enctype>` 30개가 `rendered.html`에
그대로 있지만 IR에는 **0건**, 4개 사이트 전체에서 denied attribute key **0건**,
`javascript:` href **0건**.

fixture 검증(§26)이 더 강하다. 같은 aligned HTML 안에
`action="https://original.example/save"`, `formaction="https://original.example/delete"`,
`class="secret"`, `style="color:red"`, `data-secret="ATTACK-PAYLOAD"`,
`onclick="steal()"`, `<input type=hidden value="SUPPLEMENTAL-SECRET">`,
`href="javascript:alert(1)"`, `download="x.txt"`를 심고 — **이 값들을 `dom.json`에는
일부러 넣지 않았다.** 즉 IR에 나타난다면 출처는 새 채널뿐이다.

같은 `<button>`이 `disabled`도 들고 있어서, **한 element에서 허용 1개만 복구되고 denied
6개는 전부 거절되는** 것까지 한 번에 검사한다. 그리고 SiteSpec 전체 문자열에서
`original.example` · `SUPPLEMENTAL-SECRET` · `ATTACK-PAYLOAD` · `steal()` ·
`javascript:alert` · `multipart/form-data` · `color:red` · `"secret"` · `x.txt`가
**0회**임을 확인한다.

## Current Limitations

1. **`colspan`/`rowspan` 실측 0.** 구현·fixture 검증은 끝났지만 실제 코퍼스에는 없었다.
   4개 사이트가 복잡한 표를 쓰지 않는다는 사실의 반영이지, 코드가 검증되지 않았다는
   뜻은 아니다(fixture가 두 값 모두 복구·검사).
2. **Popover / `contenteditable` 실측 0.** 같은 상황. Native Popover API를 쓰는 사이트가
   코퍼스에 없다.
3. **serialized state ≠ runtime property state.** 스크립트가 property만 바꾼 상태는
   `rendered.html`에 없고, 따라서 복구되지 않는다. IR은 그것을 안다고 주장하지 않는다.
4. **fallback viewport는 전무.** 실데이터에서는 104/104가 aligned라 발동하지 않지만,
   정렬이 깨지는 순간 그 viewport의 attribute 복구는 0이다. 부분 복구는 없다
   (Task 13의 "alignment는 전부 아니면 전무"를 그대로 승계).
5. **`headers` / `abbr` 미포함.** 표 접근성 attribute지만 실측 0이라 이번 목록에서 뺐다.
   추가는 allowlist 한 줄이다.
6. **`<li value>` 미복구.** item 8의 `value` 전면 금지를 예외 없이 지켰다.
   결과적으로 명시적 번호를 가진 `<li>`는 번호를 잃는다 (실측 0건).
7. **CLI 출력에 수치 없음.** item 39의 수정 허용 목록에 CLI가 없어서 건드리지 않았다.
   수치는 `site-spec.json.stats.supplemental*`에 있다.
