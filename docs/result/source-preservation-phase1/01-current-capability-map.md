# 01. Current Capability Map — web-recon Source Capture (pre-Phase-1)

**Date:** 2026-09-15

**Purpose:** Before implementing the Source Package (Phase 1 of Source Preservation V2), classify what the existing observer already captures for each source resource type so no duplicate system is built.

## Summary

The observer already captures the initial document's raw bytes (network response body, hashed and byte-capped) and the full runtime DOM (both as serialized HTML and as a structured element tree). For CSS, the picture is mixed: stylesheet bodies are read directly off the wire via a passive response listener, but that text is used only transiently — to bridge cross-origin/CORS-blocked sheets back into the page's CSSOM via `replaceSync` — and the CSS text itself is discarded once matched; only derived counts survive. The CSSOM itself is walked exhaustively, but the walk exists to recover per-element layout-critical declarations against a closed allowlist of ~60 properties (`LAYOUT_RULE_PROPERTIES`), not to preserve stylesheet source text, selectors, or rule order. Scripts (classic or module), network activity beyond stylesheet bodies, preload/modulepreload links, and runtime config payloads (`__NEXT_DATA__`, inline JSON, window globals) are not captured anywhere in the pipeline. Asset discovery is comparatively strong — images, `srcset`/`picture` candidates, and CSSOM-derived `@font-face` sources are all enumerated with a hardened, SSRF-safe fetch fallback — but there is no iframe provider/origin classifier, and no shared preservability vocabulary (e.g. PRESERVABLE / LOCALIZABLE / ORIGIN_BOUND) exists anywhere in the codebase to build on.

## Existing seams the Source Package must reuse

- **`navigateMainDocumentCapturingBody`** (`src/observer/navigate-document.ts:91-172`) — reads the main document's raw network response body, hashes it (sha256), enforces `MAX_DOCUMENT_RESPONSE_BYTES`, and decodes charset. Written to disk as **`document-response.html`** at `src/observer/store.ts:201-219`.
- **`captureStylesheetBodies`** — a `page.on("response")` listener at `src/observer/observe-page.ts:441-523`, installed before navigation at `observe-page.ts:1284`. This is the only existing network-body listener in the observer and the pattern any new network-log capture should extend or sit alongside.
- **`listBlockedSheetHrefsInBrowser`** (`observe-page.ts:525-542`) — detects which stylesheets threw on `cssRules` access (CORS-blocked) so the captured bodies can be matched back to their sheets.
- **The `document.styleSheets` walk** in `src/observer/collect-dom.ts:907-966` — the existing CSSOM traversal the Source Package's stylesheet-body capture must sit next to, not duplicate.
- **`deriveAssets`** (`src/observer/collect-assets.ts:92-250`) — the existing asset-discovery entry point; any new resource-type discovery (stylesheet URLs, scripts, preloads) should follow its enumeration pattern rather than inventing a parallel one.
- **`RawFrame`/`FrameObservation`** — the existing iframe capture shape to extend with a provider classifier rather than replace.
- **`safeFetchAsset`** (`src/assets/safe-fetch.ts:345-438`) — SSRF-hardened, the only allowed direct-HTTP fallback in the repo. Any new fetch path (e.g. for stylesheet URLs or scripts) must go through this, not a fresh `fetch()`.
- **`makeRunId`** (`src/observer/store.ts:66-68`) — ISO timestamp with `:`/`.` replaced by `-`; duplicated locally in `cli-reconstruct.ts:244`, `cli-compile-sitespec.ts:183`, `cli-model-interactions.ts:121`. Reuse rather than re-deriving a run id format.
- **`saveObservationIntoDir`/`saveViewport`** (`store.ts`) and the per-viewport directory layout — the existing on-disk artifact structure the Source Package should extend (new sibling files/dirs), not restructure.
- **The `SCHEMA_VERSION=5` / `READABLE_SCHEMA_VERSIONS=[3,4,5]` permissive-reader doctrine** (`src/observer/types.ts:50-69`) — new fields must be added as optional under this doctrine so old artifacts remain readable; do not break backward reads.
- **`stableStringify`** (`src/responsive-qa/continuous/json.ts:9-33`, duplicated in slotized-template) — reuse for any new deterministic JSON serialization rather than writing a third copy.
- **Existing byte caps** to respect or extend deliberately: `MAX_DOCUMENT_RESPONSE_BYTES` 8 MiB (`types.ts:827`), `MAX_STYLESHEET_BYTES` 2 MiB (`types.ts:870`), `MAX_STYLESHEET_CAPTURE_BYTES` 8 MiB (`types.ts:868`), `safe-fetch` `maxBytes` 30 MiB (`safe-fetch.ts:50`).

## What is NOT anywhere (must be new)

- **Script tag enumeration** — `SKIP_TAGS` explicitly excludes SCRIPT/STYLE/LINK (and others) from element walking at `src/observer/types.ts:460-469`. No list of `<script src>`, inline script bodies, or their attributes (type=module, defer, async) exists.
- **modulepreload/preload link enumeration** — only `rel*=icon` is enumerated (`collect-dom.ts:2759-2769`); no capture of `<link rel=modulepreload|preload|prefetch>`.
- **General network log** — only stylesheet-typed response bodies are captured; there is no `CDPSession`, no `recordHar`, anywhere in `src/`. No general request/response ledger with status/headers/timing exists.
- **Initiator evidence** — nothing in the repo attributes a captured resource to the script/stylesheet/element that caused it to load.
- **Runtime config capture** — `__NEXT_DATA__`/`application/json` script tags and `window` globals are not captured; only `ld+json` is parsed, and only from `rendered.html` (`src/seo/head-parse.ts:126-140`).
- **Iframe provider classification** — no code anywhere classifies an iframe by origin/provider (e.g. YouTube, Google Maps, payment widget).
- **A preservability vocabulary** — no `PRESERVABLE`/`LOCALIZABLE`/`ORIGIN_BOUND` (or equivalent) names exist anywhere in the repo. The closest existing vocabularies, none of which cover this axis, are:
  - `AssetClassification`: `safe-to-materialize` | `replacement-recommended` | `replacement-required` | `license-needs-review` (`src/assets/types.ts:30-46`)
  - network-qa: `local` | `source` | `other`
  - `UrlKind`: `internal` | `external` | `tel` | `mailto` | `hash`
  - `ALLOWED_HOST_SUFFIXES` + `ANALYTICS_PATTERNS` (`src/slotized-template/audit.ts:332-350`)

## Forensic V2 conclusions this phase builds on

Summarized from `docs/result/responsive-forensic-v2/09-source-truth-classification.md` and `10-architecture-recommendation.md`:

- Authored declarations exist in the observation spec but 83% are not consumed downstream — classified as `AVAILABLE_BUT_NOT_CONSUMED`, meaning the gap is largely in what later stages read, not only in what the observer captures.
- The observer stale-handle blind spot (973 nodes) is a real upstream defect but is explicitly **out of scope** for this phase — it belongs to the observer/probe layer, not the Source Package.
- Swiper JS geometry values are captured (via layout probing) but without the relation that connects them back to their controlling script/library — the numbers exist without their causal link.
- The site stack under study is Next.js (pages router) + MUI/emotion CSS-in-JS + Swiper + AOS — so CSS-in-JS runtime `<style>` tags whose `textContent` is empty while the CSSOM still holds the rules are the **expected**, not anomalous, case for this stack.
- The recommended architecture is source-preservation-first (referred to as "hybrid D") — capture and preserve authored source before any lossy conversion, rather than deriving everything from computed/runtime state as today's pipeline does.
