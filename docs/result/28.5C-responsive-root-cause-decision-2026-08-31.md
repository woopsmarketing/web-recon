## Executive Summary

The success definition of this task was to be able to say, in plain language, *"1100px breaks because THIS exact information/rule is lost HERE."* We can now say it:

> **linear.app /pricing breaks at 1100px because the observer never samples any width between 1024 and 1440, and `hiddenRanges()` (`src/reconstruction/layout-inference.ts:661-684`) fills that 416px hole by interpolating per-node hidden bands to arithmetic midpoints — emitting `@media (min-width:1024px) and (max-width:1231.98px) { display:none }` for 503 nodes on /pricing, when the source's real switch is at exactly 1025px. The rule ships unverified by design: the post-emit truth check renders only at 1440, a width at which this band can never apply, so all 738 such rules in the stylesheet are `acceptedUnchecked`.**

And the simplest generic fix direction is identified and demonstrated: **Strategy C — minimal inference correction** (correct the hidden bands instead of extrapolating them; unfreeze provably-fluid nodes with `width:auto` only; convert frozen px grid tracks — including single-track grids — to `fr`; add one probe width in the gap). A disposable emulation of it (**AC5**) achieved **0 blockers at all five required widths** (390/700/1024/1100/1440) on /pricing, restored the full five-column comparison table at 1100 (offscreen chars 105→0), cleaned 1024 completely (305→0 offscreen), and ran on Stripe with zero code changes and zero regression (after one mandatory correction the Stripe check itself discovered).

Why the verdict is nevertheless *more experiment needed* and not *ready to implement*: the fresh adjudicator independently confirmed that the winning variant, wherever it acts, introduces a systemic MAJOR-class defect with one shared signature (lost flex justification / lost row gaps: jammed logo rows, a nav cluster ~280px out of position at 1440, colliding table cells at 1024) that the clip metric does not see; the one required width no strategy moved (700 — the frozen mobile subtree) has an identified fix that was never once emulated; and the winner's band behavior depends on the extra 1100 probe sample in a way its own description mislabeled. Three bounded experiments stand between this investigation and a production implementation task — none of them is an architecture redesign.

## What Responsive Means in web-recon

The product requirement (Section 3 of the task) is deliberately narrow: **not** continuous responsive equivalence, but a professional, content-preserving, non-broken layout at five acceptance widths: **390, 700, 1024, 1100, 1440**. The adjudicator's framing is the right one to carry forward: the honest deliverable is *"verified at five widths"*, explicitly not *"responsive"*. A discrete band switch is fully compatible with a discrete five-width promise — provided every promised width is actually rendered and compared before shipping.

## Current Responsive Reconstruction Flow

(Full map with file:line evidence: `28.5C-responsive-pipeline.json`.)

1. **Observation** captures exactly **two deep viewports** — desktop 1440×900 and mobile 390×844 (`src/observer/types.ts:112-140`) — plus a **five-width geometry probe** `[390, 768, 1024, 1440, 1920]` (`types.ts:1103`) that re-measures parked element refs at each width. A `probeExtraWidths` option exists (`observe-page.ts:125/:448`) but no CLI plumbs it; `multi-observer/observe-selected-pages.ts:287` drops it.
2. **SiteSpec** carries both viewport trees verbatim. Source `@media` condition text is captured into `authoredLayout[].media` — and then never used for emission.
3. **Reconstruction** ships **both subtrees in one document** as `[data-wr-viewport="desktop"|"mobile"]` siblings, switched at an **inferred** breakpoint: `floor((390+1440)/2) = 915` (`responsive-plan.ts:74-81`; provenance is literally `inferred`, never `observed`).
4. **Layout inference** emits a fluid tier for a narrow class of nodes and freezes everything else at the observed computed px. Per-node hidden bands are synthesized from probe visibility toggles (`hiddenRanges`, `layout-inference.ts:661-684`).
5. **Truth check** (`layout-truth-check.ts`) renders post-emit — but only at 1440, so `responsive-hidden` rules are the one rule kind that always ships `acceptedUnchecked` (`:46-51,:107`; confirmed 738/738 in the shipped manifest).

## Why Width Bands Freeze

Three compounding causes, all verified in code and live:

- **The mobile subtree receives zero inferred rules.** `generateLayoutCss` hardcodes `data-wr-viewport="desktop"` (`layout-inference.ts:701`), so 0–914.98px renders the mobile tree bit-frozen at 390px-resolved values — the familiar 390px left-pinned column with a ~310px dead band at 700.
- **The desktop subtree is frozen at 1440px-resolved values.** The source's fluid forms (`2fr repeat(4,1fr)`, `clamp()`, `vw`, `%`) are captured verbatim in the IR and then discarded in favor of the browser's resolved px at the observation width — a consequence the repo itself documents (`observer/types.ts:404-411`).
- **The fluid tier barely fires.** It stands on three usable samples ([1024,1440,1920] after 768 falls below the 915 breakpoint) and is further narrowed by the blockish-display gate and the 28.5B containing-block guards, which refuse grid items and basis-governed flex items outright — so most interior boxes of a modern grid/flex page fall to the frozen tier by design.

## Exact /pricing 1100 Failure Chain

(Full five-stage trace per node: `28.5C-pricing-1100-trace.json`.)

- **Source @1100:** header row `Features | Free | Basic | Business | Enterprise` visible; kept by an *unconditional fluid* rule `.PDOlRq_row { grid-template-columns: 2fr repeat(4, 1fr) }` (resolves 360+180×4 at 1100; 448+224×4 at 1440). The source's only relevant switch is `@media (max-width:1024px) { .hide-laptop { display:none !important } }` / `@media (min-width:1025px) { .show-laptop { display:none !important } }`.
- **Observation:** probe visibility for the header region: `[0,0,0,1,1]` at [390,768,1024,1440,1920]. The measurement at 1024 is *correct* (source is genuinely in mobile mode at 1024). **The first loss is a missing sample**, not a wrong value: the true 1025 edge sits inside the unsampled 1024–1440 hole.
- **Reconstruction (where the defect materializes):** `hiddenRanges()` sets the band start at the sample width and the end at `floor((1024+1440)/2) − 0.02 = 1231.98` (`layout-inference.ts:674,677-678`). Emitted, adjudicator-confirmed verbatim in the shipped sheet (`generated-styles.css:13541-13545`, node `n000359`):

  ```css
  @media (min-width: 1024px) and (max-width: 1231.98px) {
  [data-wr-page="p000007"][data-wr-viewport="desktop"] [data-wr-node="n000359"] { display: none; }
  }
  ```

  738 such blocks in the sheet — **all at this single condition** — 503 of them on /pricing (the "~503 hidden nodes"). Specificity (0,3,0) outranks the node's own style.
- **The band is wrong at BOTH edges** (new finding, corrects 28.5B): the clone also wrongly *shows* desktop table content at 950–1023 where the source hides it. 28.5B's "lower edge is right" was a coincidence of two errors.
- **Second, independent cause at 1100:** even with the band removed, the desktop tree renders 1344px of frozen grid track inside an 1100px viewport with no overflow management — 250 chars offscreen and unreachable (scrollWidth == innerWidth).
- **Baseline correction:** 1024 was **already a BLOCKER** in the shipped build (Enterprise card, right nav, footer column fully offscreen) — not merely the 390-column residual 28.5B recorded.

## Source Responsive Behaviour

(Full inventory: `28.5C-source-responsive.json`.)

Linear's responsiveness is **100% declarative CSS** — desktop-first `max-width` breakpoints at 640/768/1024/1280 plus small `.hide-*/.show-*` utilities toggling permanently-present parallel subtrees. **Verified identical with JavaScript disabled at all five widths**, including the mobile plan `<select>`, which re-renders 57 rows purely via `:has(option:checked)`. DOM node count is byte-identical (3,246) at 390/1024/1100/1440 — nothing restructures on resize. `@container` exists only in the video player/charts. Six `:root` media rules re-define breakpoint tokens — exactly what a two-viewport computed-style capture flattens away.

## What Information We Currently Throw Away

1. **Source `@media` conditions** — captured into `authoredLayout[].media`, used only to *exclude* rules from an evidence string, never emitted.
2. **Almost all authored layout, due to a CORS trap** (the single highest-leverage discovery of this task, reproduced on both sites): 30/81 Linear stylesheets — precisely the load-bearing ones — throw `SecurityError` on `cssRules` because the SSR `<link>` tags lack `crossorigin`, while the server itself sends `access-control-allow-origin: *`. Direct fetch recovers **81/81** sheets. Consequence measured by the adjudicator: `authoredLayout` present on **34 of 3,254** /pricing nodes (only condition captured: `(max-width:640px)`); Stripe **0 of 2,280**. The generator is inferring band edges and grid tracks that the source *tells us outright* (`1025`, `2fr repeat(4,1fr)`) — we just fail to fetch them.
3. **Authored fluid forms** (`fr`, `clamp()`, `vw`, `%`) — captured verbatim, then replaced by resolved px.
4. **`@container`/`@supports` declarations** — recursed into and recorded *as if unconditional* (a correctness bug, low severity here).
5. **Original class/data attributes** — present in the observation (`PDOlRq_row` ×429, `data-plan` ×228) but stripped by the SiteSpec compiler; the served clone has 0 occurrences. (This corrects Agent C's optimism and is why Strategy B needed a translation layer.)

## Strategy A — Additional Observation

Re-observed with `probeExtraWidths:[700,1100]` (7-width probe), respliced, rebuilt. **Result: rejected as a standalone fix.** Its output was *identical in every measured field* to the ten-line band clamp: more truth samples buy nothing while the geometry tier is gated by the containing-block guards, and 700 never enters the desktop sample set (700 < 915). Blockers 2 (1024, 1100), majors 1 (700). One piece of A is indispensable, though: **a single extra probe width near 1100** — the unfreeze detector finds 508 fluid nodes with it and only 9 without, because Linear caps its layout near 1440 (the 1440/1920 pair is blind) and 1024 is already mobile-mode.

## Strategy B — Selective Responsive Rule Preservation

Fetched all 81 sheets (bypassing the CORS trap), kept 621 width-conditioned/load-bearing rules, translated selectors through a `sourceElementId`→class layer (220 rules, 0 selector failures), respected `@layer` order. **Result: rejected outright.** It regressed 1440 — the one previously-exact width (both `.hide-laptop` and `.show-laptop` content rendered simultaneously), produced duplicated stacked CTAs and colliding cards at 1100, and would reintroduce a build-time dependency on source stylesheet fetching, surrendering Task 22's asset independence. Preserved rules replayed against a frozen-px DOM fight the generated cascade; the two style systems do not compose. Blockers 2, majors 2 — the worst of the three.

## Strategy C — Minimal Inference Correction

Emulated by writing the CSS a corrected generator would emit, in three iterations:

- **C/AC3 (initial winner):** clamp hidden bands + unfreeze fluid nodes (`width:auto; max-width:none`) + px→fr for multi-track grids + 1100 probe. Only variant to clean 1024 and fit all four plan cards at 1100 — but the visual audit found it introduces defects wherever it acts.
- **AC4 (Stripe-mandated correction):** drop `max-width:none` — it destroys authored max-width caps (cause of the flattened/clipped CTA headline at three widths). Confirmed on Linear: headline restored everywhere.
- **AC5 (final best):** additionally convert *single-track* frozen grids (`grid-template-columns:1344px` → `minmax(0,1fr)`) — that single track was the min-content pin holding ancestors at 1436px. 1100 offscreen chars 105→**0**; 1024 overflow 78→**0**. (The transitive-unfreeze hypothesis was tested and measured zero effect — the pin was the single-track grid, not descendant re-pinning.)

Production shape implied: **three bounded edits in two files** (probe widths; `hiddenRanges` correction; coherent fluid-unfreeze emission), no schema change, no runtime dependency, no new concepts.

**Honest caveats, adjudicator-verified:** (1) AC5's shipped bands actually end at `1061.98` = midpoint(1024,1100) — the measured result depends on the extra probe sample, and clamp-alone would differ across 1025–1061; (2) wherever the unfreeze acts it currently trades frozen-width defects for lost flex justification/row gaps (see below).

## Stripe Generalization

(`28.5C-generalization.json`.) The mechanism ran on stripe.com's reconstruction with **zero code edits and zero selector-assumption failures**: 1,906 nodes unfrozen, 78 grids converted, 1100 BLOCKER→MAJOR. The band-clamp half is a provable no-op there (Stripe's generated sheet has zero `@media` blocks — the destructive-band pathology is probe-toggle-dependent, not universal). The initial form *did* regress Stripe at 1440 — which is how the mandatory `max-width:none` correction was found and verified in both directions. Verified generalization requirements: emit `width:auto` only, and choose the probe pair from the site's top *authored* layout switch (Stripe's is 940 → pair (1024,1440) finds 782 fluid nodes; (1440,1920) finds 28). The CORS capture trap and the frozen-mobile-subtree residual both reproduced on Stripe — these are engine facts, not Linear facts.

## Simplest Winning Strategy

**Strategy C + one extra probe width (AC5 form), with the coherent-property-set completion still to be proven.** The A>B>C preference order was honored and both A and B were given real experiments; they failed on evidence, not on taste. C's production change is the smallest of the three by every measure.

## What We Should NOT Build

Confirmed rejections (none needed even to reach 0 blockers): Universal Responsive Solver, CSS theorem engine, ML breakpoint prediction, LLM-generated responsive CSS, a new page builder, a new reconstruction architecture, Linear-specific selectors in production, and **full source-stylesheet replay** (Strategy B's failure retires the old Full-CSS idea for responsive too).

## Proposed Production Change (for the follow-up task — NOT implemented tonight)

Five work packages, from the adjudication (`28.5C-adjudication.json` carries the full scope):

1. **Hidden-band correction** in `hiddenRanges()` — never extrapolate a hidden band past the widths observed hidden; use authored breakpoints (WP4) as edge input when available. Kills all 738 wrong blocks. (~10 lines)
2. **Probe-width plumbing** — surface `probeExtraWidths` through the CLI/multi-observer; default the probe set to include the acceptance widths (700, 1100); choose the fluid-detection pair from the site's top authored layout switch.
3. **Coherent fluid-unfreeze emission** — `width:auto`-only, px→fr including single-track grids, and the frozen property *set* (margins, justification-bearing properties, footer tracks) treated as one unit per fluid subtree. **This is the open experiment**: it must clear the lost-justification/row-gap signature without regressing 390/1440.
4. **Authored-breakpoint capture (CORS fix)** — fetch stylesheets directly when CSSOM access throws; populate `authoredLayout` for real. Highest leverage per line changed; benefits both WP1 and WP3.
5. **Close the verification hole** — extend the layout truth check to render at every promised width so `responsive-hidden` (and unfreeze) rules can never ship `acceptedUnchecked` again. The adjudicator made this a mandatory fourth clause of the architecture principle.
6. **(700)** Lift the hardcoded `data-wr-viewport="desktop"` at `layout-inference.ts:701` and generate rules for the mobile subtree below the breakpoint — identified, bounded, and the one required width with no experimental evidence yet.

## Human Acceptance Criteria

At each of 390/700/1024/1100/1440, rendered and compared against source: 0 BLOCKERs; no MAJOR regression at any width that is faithful today (390, 1440); comparison table complete at 1024+; nav left/right anchoring and logo-row spacing correct; no offscreen normal-flow text; 700 no longer renders a 390px column. AC5 as it stands would **fail** this bar at 1440 — that is by design of the bar.

## Remaining Fidelity Work After Responsive

Unchanged from 28.5B: fonts (licensing-gated), QA video frame pinning, stripe `background-clip:text` knockout, audio assets, `cli-reconstruct` not printing `rejectedUnverifiable`. New from this task: `@container`/`@supports`-as-unconditional capture bug; SiteSpec attribute stripping (matters if any future feature wants source class/data hooks).

## Architecture Principle Adjudication

**PRESERVE → OBSERVE → INFER: ADOPT, NARROWED, PLUS VERIFY.** The evidence supports *preserve* as a **capture/IR principle** (authored breakpoints, fluid forms, and media conditions must reach the IR — the CORS fix) and as a **constraint on inference** (never infer an edge the source declares). It **refutes** *preserve* as a **rendering principle** — Strategy B replayed genuine source rules and produced the worst result of the three. And the task's central lesson adds a fourth clause the proposal omitted: **VERIFY** — the exact rule kind that shipped without ever being rendered is the one that carried a 207px band error into the release.

## Final Verdict

**RESPONSIVE ROOT CAUSE KNOWN — MORE EXPERIMENT NEEDED.**

The root cause is proven at file:line and reproduced live by an independent adjudicator; the simplest fix direction is chosen on evidence (A and B experimentally eliminated); the fix is small, generic (two sites), and needs no redesign. It is not "ready to implement" because three bounded questions remain experimental: the coherent-property-set unfreeze (the one shared defect mechanism), the never-emulated mobile-subtree fix for 700, and authored-breakpoint capture as the band-edge input. The user and external reviewer choose whether to authorize the production task (proposed: 28.5D, scope above).
