## 4. 초기 문서 캡처 (P0-C)

## 5. Inline 캡처

- **수집:** 런타임 선언을 `element.style`에서 수집합니다. 속성·값·important를 기록하고, 요소당 상한이 있으며 `truncated` 표시를 둡니다.

- **var() shorthand:** 빈 longhand로 풀리면 원문을 기록하고 `truncated`와 `unresolvedShorthands`를 표시합니다(리뷰 M1).

## 6. 초기↔런타임 대응 (never guess)

- **대응 요소 찾기:** parse5로 초기 HTML의 요소를 구조 경로와 id/class/text 서명으로 찾습니다(`src/observer/inline-provenance.ts:691`). 형제 중 유일하지 않으면 `ambiguous`, id가 충돌하면 `no-initial-node`(`id-conflict`)입니다.
- **분류 규칙:**

| 분류 | 조건 |
|---|---|
| `initial-static` | 정확히 증명 가능한 정규화 후 값이 동일 |
| `initial-mutated` | 직접 비교 가능하고 증명 가능하게 다름 |
| `runtime-added` | 초기 inline에 해당 longhand를 만들 수 있는 선언이 전혀 없음 (Chromium 속성표 기반 shorthand 확장) |
| `runtime-responsive` | probe 폭 사이에서 값이 달라지고 시간 변동이 아님 |
| `unknown` | 그 외 전부. 사유를 기록 |

- **리뷰 B2 반영:** 색 직렬화나 `flex:1` 같은 추측은 제거됐습니다.

## 8. Cascade 알고리즘 (P0-D)

`resolveCascade`(`src/reconstruction/responsive-decl/cascade.ts:148`)는 폭 W에서 다음 순서로 승자를 정합니다.
1. **중요도/출처:** author normal < author !important.
2. **element-attached:** 같은 중요도에서 inline이 sheet를 이깁니다(normal inline < important sheet < important inline).
3. **layer:**
   - normal에서는 unlayered가 layered보다 이기고, 나중 layer가 이깁니다.
   - important에서는 순서가 반전됩니다.
   - 익명 layer는 `(anonymous-N)`으로 식별만 하고 출력하지 않습니다.
4. **specificity.**
5. **order:** sheetIndex, ruleOrder 순.

**조건부 선언:** 조건은 `mediaToIntervals`(`intervals.ts:251`)로 [min,max) 구간이 됩니다. 폭 외 media feature는 "적용 가능"으로 두되, 승자를 바꿀 수 있으면 ambiguous입니다.

**Truncation:**
- 속성당 8개, 요소당 96개 상한입니다. 현재 폭에서 적용 중인 규칙을 먼저 두고, cascade 우선순위 순으로 유지합니다(리뷰 M2).
- 잘린 경우 planner가 ambiguous로 처리하고 카운터(`layoutRulesMatched/Kept`)를 남깁니다.
- `@media`/`@supports` 불일치 안의 `@layer`는 layer 순서에 넣지 않습니다(리뷰 m2).
