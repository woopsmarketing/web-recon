## Polish 변경 (1.3.0 → 1.3.1)

스타일만 바뀌었습니다. HTML, 콘텐츠, 설정, 동작은 1.3.0과 같습니다. `index.html`의 **Polish 변경** 그룹 ①–⑤에서 같은 스크롤 위치의 전후를 나란히 봅니다.

1. **모바일 footer**(①): 900px 미만에서 한 열로 쌓입니다. 브랜드 → 요약 → "Company" 라벨 위 값 → "Email" 라벨 위 값 순서입니다. 긴 회사명과 이메일은 줄바꿈되고 가로로 넘치지 않습니다. 900px 이상은 1.3.0과 같습니다.
2. **떠 있는 상담 버튼**(②): 모든 폭에서 viewport 우하단의 한 자리(모바일 16/16px, 900px 이상 24/50px, safe-area 더함)에 고정됩니다. 앞으로 채팅 런처가 같은 자리를 씁니다(구현하지 않음). pill 모양은 유지했습니다. footer 아래 여백은 이 자리에서 계산되므로, 페이지 끝에서도 footer 글자를 가리지 않습니다.
3. **후기 간격**(③): 후기가 모두 한 화면에 들어가면 레일, 버튼, 그 자리가 모두 사라집니다. 넘치면 레일과 이전/다음 버튼은 그대로입니다. 600–899px에서는 후기가 한 줄(01 → 02 → 03)로 읽힙니다.
4. **포트폴리오 목록 상단**(④): 제목과 소개가 배너 아래쪽 위에 올라가고, 글자 뒤에는 글에 고정된 scrim이 깔립니다. 필터와 검색은 배너 바로 아래에 옵니다. 필터 동작, 검색, 정렬, URL은 1.3.0과 같습니다.
5. **일관성**(⑤): 카드 제목 크기는 사이트 전체에서 하나입니다. 페이지네이션은 40px 버튼이고 현재 페이지가 채워진 원입니다. 필터 패널은 상자 대신 위아래 선입니다. 쇼케이스 A → B는 한 리듬으로 붙고, 안쪽 페이지는 footer 앞에 96px이 있습니다.

**Step 5의 "모바일 footer가 잘림"은 캡처 착시였습니다.** 1.3.0 모바일 홈 화면(02, 07)은 캡처 도중 터치 에뮬레이션의 pointer 미디어 쿼리가 바뀌어 트랙 버튼 3줄(126px)이 나타났습니다. 그런데 캡처 크기는 그 전에 정해져서 페이지 끝 126px이 빠졌습니다. 실제 페이지는 잘리지 않았습니다. 1.3.1 화면은 문서 높이 전체를 찍었고, 높이를 검증했습니다.

**수용한 결정(바꾸지 않음):** 불투명 header, 선택적 hero 문구와 CTA, 쇼케이스 A/B 공용 배치, 모바일 약 84% 카드 peek, 현재 최대 폭(1920으로 넓히지 않음), 상세 구조, 안쪽 페이지의 pre-footer 띠 없음, 햄버거 메뉴 없음, hero 문구 들여쓰기, pause/play, 축소된 footer.

## 1. 무엇을 보아야 하는가

**화면 구조와 반응형 거동**을 봅니다. 콘텐츠 자체는 보지 않습니다.

1. **섹션 순서와 뼈대.** 순서가 header → hero carousel → intro(이미지 + 글) → 프로젝트 쇼케이스 A → 쇼케이스 B → 후기 → 이미지 밴드 → footer인지 봅니다. 원본 홈과 같은 흐름으로 읽히는지 봅니다.
2. **간격과 리듬.** 섹션 사이의 상하 여백이 일정한지, 좌우 여백(데스크톱 40px 기준선)이 섹션마다 맞는지, 어색하게 빈 구역이 없는지 봅니다.
3. **타이포 위계.** 섹션 제목, 카드 제목, 요약, 메타 텍스트가 크기와 굵기로 구분되는지 봅니다. 줄바꿈이 부자연스러운 곳이 없는지도 봅니다.
4. **카드 트랙(쇼케이스, 후기).** 한 화면에 보이는 카드 수(데스크톱 3, 600–899px 2, 모바일은 약 84%에 다음 카드가 살짝 보임), 진행 레일, 이전/다음 버튼의 위치와 정렬을 봅니다.
5. **폭별 전환.** 폭은 390, 800, 1000, 1440, 1920을 봅니다. 900px을 기준으로 모바일 배치에서 데스크톱 배치로 바뀝니다. 800은 "넓은 모바일", 1000은 "좁은 데스크톱"이고, 1920에서는 콘텐츠 최대 폭과 좌우 여백이 자연스러운지 봅니다.
6. **데이터 양에 따른 fallback.**
   - fixture-small: 한국어 문구에서 줄바꿈과 글자 폭이 자연스러운지 봅니다. 섹션 구성은 fixture-large와 다릅니다.
   - fixture-empty: 데이터가 없는 섹션이 빈 틀 없이 **통째로 빠지는지**, hero와 텍스트 intro만으로 페이지가 어색하지 않은지 봅니다. 이 fixture에는 내비게이션이 없고 `/portfolio`는 404입니다.
7. **다른 페이지와의 일관성.** 포트폴리오 목록과 상세 페이지의 header, footer, 여백, 타이포가 홈과 같은 사이트로 보이는지 봅니다. 이 두 페이지의 HTML은 1.3.0과 같고(1.3.0의 `<main>`은 1.2.0과 같음), 1.3.1에서는 스타일만 바뀌었습니다. 포트폴리오 상단(Polish ④)과, 홈과 나란히 놓였을 때 어울리는지를 봅니다.

## 3. 판정하지 말아야 할 것

- **사진과 일러스트.** 후보 이미지는 모두 생성한 가상 SVG 일러스트입니다. 사진의 질감이나 분위기는 원본과 비교할 수 없고, 목표도 아닙니다.
- **문구와 브랜드.** "Harbor & Pine", "마루 아틀리에 (가상)", 후기 문장, 프로젝트명은 전부 fixture 데이터입니다. 내용의 좋고 나쁨이나 길이 차이는 보지 않습니다.
- **fixture 테마의 색 값 자체.** 색 조합의 취향은 보지 않습니다. 대비와 가독성 문제만 봅니다.
- **원본 콘텐츠.** 원본 사진, 문구, 로고, 노란 이미지 톤 등은 복제 대상이 아닙니다. 원본 화면은 **배치 참조용**으로만 씁니다.
- **캡처가 만든 착시.**
  - full-page 캡처에서는 떠 있는 상담 버튼(position: fixed)이 **캡처 순간의 화면 위치에 한 번만** 찍힙니다. 그래서 페이지 중간 엉뚱한 곳에 보일 수 있습니다. 실제 버튼은 항상 화면 우하단에 있습니다.
  - hero는 캡처 순간에 활성이던 슬라이드가 찍힙니다. 폭마다 다른 슬라이드가 보일 수 있습니다.
  - full-page 캡처는 svh 기반 높이를 바꿀 수 있습니다. hero 높이의 정밀 판단은 이 pack이 아니라 실제 브라우저 창에서 해야 합니다.
  - 원본 모바일 화면은 390px 폭을 3배로 찍은 것(1170px)입니다. index에서는 390 CSS px 폭으로 줄여 보여 줍니다.
  - 원본 800, 1000 참조는 in-place 창 크기 변경 캡처(899/900, 첫 화면만)이고 full-page가 아닙니다. 1920은 원본 캡처가 없습니다.

## 4. 알려진 polish 잔여(06-open-items.md에서 옮김)

1.3.1 상태: 1은 부분 해결(후기 한 줄, footer 한 열), 2는 해결, 3은 자리 계약과 hit-test로 해결(pill 유지), 5와 6은 수용한 결정, 나머지는 그대로입니다. 새 open item은 `docs/result/recon-template-platform-whole-site-polish/04-open-items.md`에 있습니다.

이 항목들은 Step 5에서 기록되었고, Whole-site Visual / UX Polish에서 다뤘습니다. 화면에서 보이더라도 **새 발견이 아니라 알려진 항목**입니다. 다만 심각도에 대한 사람의 판단은 이 검토에서 받습니다.

1. **600–899px 구간.** 트랙은 2개씩 보입니다. 나머지는 모바일 레이아웃을 늘린 형태입니다: 키 큰 hero에 28px 헤드라인, 왼쪽에 440px로 제한된 intro 이미지.
2. **후기 뒤 빈 공간.** 후기 배너 이미지가 없고 후기가 모두 한 화면에 들어가면(예: 1440에서 3개), 숨겨진 트랙 바가 자리를 차지합니다. 이미지 밴드 앞에 약 200px의 빈 공간이 생깁니다.
3. **떠 있는 상담 pill.** 일부 스크롤 위치에서 텍스트 줄 끝이나 트랙의 "다음" 버튼 위에 겹칠 수 있습니다. 900px 미만에서는 아이콘만 있는 원형으로 바꾸는 방안을 검토합니다.
4. **쇼케이스 A/B의 "View all"이 모두 `/portfolio`로 갑니다.**
5. **불투명 header.** 의도적인 차이이며 polish 후보입니다.
6. **hero 문구 들여쓰기.** 900px부터 약 1576px까지 슬라이드가 여러 장인 hero는 문구가 x=108에서 시작합니다(화살표를 피하기 위해서). 그래서 다른 섹션의 40px 좌측선과 맞지 않습니다.
7. **최대 길이 문구가 hero를 키웁니다.** 320–390px 폰에서는 hero가 화면 높이를 넘을 수 있습니다(320에서 784px). 잘리지는 않습니다.
8. **데스크톱 탭 순서.** 900px 이상에서는 "View all" pill이 오른쪽 위에 보이지만 DOM에서는 트랙 뒤에 있습니다. 그래서 카드 뒤에 포커스가 위로 되돌아갑니다. 이미 수용한 항목입니다.
9. **후기 목록 탭 정지.** 크기 변경이나 확대로 스크롤이 필요 없어지면 탭 정지가 사라집니다. 드물고, 수용했습니다.
10. **브라우저 커버리지.** Chromium에서만 확인했습니다. WebKit/Gecko 확인은 Pre-Demo gate에서 합니다.
11. **늦은 폰트 교체.** 긴 문구와 늦은 웹폰트 교체가 겹치면 줄 수가 바뀔 수 있습니다. 지금 테마는 시스템 폰트여서 해당하지 않습니다.
12. **dropped-destination 경고는 섹션 설정을 읽지 않습니다.** 비활성 섹션의 목적지까지 경고에 이름이 나옵니다.
13. **reduced motion.** 사용자가 처음 탐색하기 전까지 hero의 `aria-live`는 "off"입니다.
14. **autoplay는 CSS 애니메이션에 의존합니다.** 애니메이션을 끄면 autoplay도 멈춥니다. 의도한 fail-safe입니다.

이 pack에서 **직접 보이는 것**은 1, 2, 3(겹침 위치), 4(링크라서 화면으로는 확인할 수 없음), 5, 6입니다. 나머지는 동작이나 접근성 항목이라 캡처로 판단할 수 없습니다.
