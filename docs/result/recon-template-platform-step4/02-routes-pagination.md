# 02 — Routes, pagination, navigation, SEO files

## Declared routes (Template manifest)

`templates/interior-01/v1/template.ts` declares which content generates each App Router page. The Next.js App Router remains the router.

| key | App Router pattern | source |
|---|---|---|
| `home` | `/` | always |
| `portfolio.index` | `/portfolio` | projects list, page 1 (static route) |
| `portfolio.page` | `/portfolio/page/[n]` | projects list, pages **2…N** only |
| `portfolio.detail` | `/portfolio/[slug]` | one page per served project |

- `pageSize = 30` is declared once (`PORTFOLIO_PAGE_SIZE`). The observed design is 10 rows × 3 columns.
- Page 1 exists only as `/portfolio`. `/portfolio/page/1` is never planned, so it is never emitted.
- Source defects are not copied: no `?page=0`, no `?TOGGLED_UUIDS=[]`, and no redirect to `/` for an invalid id.

## Route plan (`platform/site/routes.ts`, new, pure)

`planRoutes(template.routes, reader)` is the **single source** for:

- `generateStaticParams`: `ctx.routes.params(key)`
- nav and link availability: `ctx.routes.has(key)`, used by the header nav, the home "view all" link and the detail back link
- `app/sitemap.ts`: `ctx.routes.paths()`
- build-time pruning, recorded in `build-record.preflight.pruned`
- exclusive package QA: exactly the planned HTML pages plus the framework `404.html` and `_not-found.html`; any other `.html` is a failure

**Declaration validation (build fails)**
- Only kebab static segments or one `[param]`.
- Unique keys and patterns.
- `pageSize` is an integer 1–500 and consistent per collection.
- The first list page is static. List-rest and item routes have exactly one dynamic segment, in the last position.
- No URL is generated by two routes.

**Reserved slugs**
- For each item route, the reserved set is its static sibling segments (`page`) plus the platform-reserved `index`. A static export would write `/portfolio/index` as `portfolio/index.html`, which static hosts also serve for `/portfolio/`.
- A **served** project with a reserved slug is a **build/preflight FAIL** with an actionable message (test I).
- A preview build includes drafts, so it fails the same way.
- A public build **warns** about unserved (draft or scheduled) projects that hold a reserved slug, before publish day (`unservedSlugWarnings`).

**Builder compatibility.** The builder is not part of any release. `normalizePreflight` therefore also accepts the 1.0.0 preflight shape (raw static manifest routes, no prune). A site re-pinned to `interior-01-1.0.0-f27823c3b837` still builds with the current builder (test "Y rollback by re-pin").

## Pruning: an internal build workaround only

- **Why it exists.** With `output: "export"`, Next 16.3.0 aborts on an empty `generateStaticParams`. It throws E1452 in `next/dist/build/index.js`, and this was confirmed earlier in Step 0.
- **Why `notFound()` is not enough.** A static route that calls `notFound()` still emits an HTML page.
- **What the builder does.** After preflight, in the disposable workspace (never in the release or the repo), it deletes route files that generate no page (`pruneRoutes`, `platform/build/site-build.ts`).
  - Every entry is re-validated: route-dir grammar, containment in `app/`, and the directory must exist.
  - `segment` scope requires a dynamic dir and removes it. `page` scope removes exactly one `page.*` file.
  - Directories left empty are swept.
- **Scope.** This is not a content or Template concept. The Template code is identical for every site.

| site | visible projects | generated | pruned |
|---|---|---|---|
| fixture-large | 173 | `/` + `/portfolio` + `/portfolio/page/2…6` + 173 details = **180 pages** | — |
| fixture-small | 12 | `/` + `/portfolio` + 12 details = 14 | `portfolio.page` |
| fixture-empty | 0 | `/` | `portfolio.index`, `portfolio.page`, `portfolio.detail` |

**Not-found behaviour**
- `dynamicParams = false` on both dynamic routes, so unknown slugs and page numbers are not generated.
- The `[n]` route also calls `notFound()` for any non-canonical number (such as `01`, `1` or `7`), in case a param ever slips through.
- A static host serves `404.html` for these URLs (tests G/H and the visual smoke).

## Pagination UI (`components/Pagination.tsx`)

**Structure**
- Real crawlable `<a href>` links for pages: `/portfolio` and `/portfolio/page/n`.
- The current page is a non-link with `aria-current="page"`.
- Prev/next are links with `rel`. At either end, the missing step is an `aria-hidden` span.
- The window shows all pages when there are ≤7. Otherwise it shows 1 · … · 5 around the current page · … · last, matching the observed `‹ 1 2 3 … 22 ›` style.
- It renders only when pageCount > 1.

**Labels**
- These are slots on `portfolio.index`: `pageLabel`, `previousLabel`, `nextLabel`, `paginationLabel`.
- fixture-small overrides them in Korean.

## Navigation

- **Header.** "Projects" is `<Link href="/portfolio" data-nav="portfolio">` only when `portfolio.index` exists. It has `aria-current="page"` on `/portfolio`, and `aria-current="true"` on later list pages and details. The Slice 1 `#projects` anchor was replaced, because the list page is its destination now.
- **Home cards** link to `/portfolio/<slug>` (test R). The "view all" link to `/portfolio` renders only when the route exists. Its label is the `home.projects-a.moreLabel` **text** slot, and its href is Template-owned.
- **LINK_SLOT_USED = NO.** Every new destination is a Template route that must disappear with its route. A site-editable href could point at a pruned page. The detail CTA uses the business contact email, the same pattern as the header contact link.

## SEO (`lib/seo.ts`, `app/sitemap.ts`, `app/robots.ts`)

**Metadata**
- Uses the Next metadata APIs (`generateMetadata`).
- Home behaviour is unchanged: brand title, business summary, no canonical.
- List titles:
  - `/portfolio` → `<title slot> | <brand>`
  - `/portfolio/page/n` → `<title> — <pageLabel> n | <brand>`, so each page has a unique title.
- Detail title: `<project title> | <brand>`, with description = `summary` (only when present).

**Canonical**
- `alternates.canonical` is emitted **only when the site declares a real `publicOrigin`**.
- No domain is fabricated. With no origin, there is no canonical.

**Preview mode**
- `noindex, nofollow` (from the Slice 1 layout).
- `robots.txt` = `Disallow: /` with no sitemap line.
- `sitemap.xml` has no URLs.

**Public mode**
- `robots.txt` = `Allow: /`, plus a `Sitemap:` line only when an origin exists.
- `sitemap.xml` = exactly `ctx.routes.paths()` on the origin: 180 / 14 / 1 URLs (test T).

**Not emitted:** structured data, `lang="kr"` (the locale comes from site identity: `en-US`, `ko-KR`, `en-GB`), and the source's malformed SEO.
