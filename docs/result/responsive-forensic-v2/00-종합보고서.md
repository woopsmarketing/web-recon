## 1. 실행 판정 (≤7문장)

"responsive split-brain" 가설은 **입증**되었으나, 그 1차 형태는 노드 간 분열이 아니라 **속성군 간 분열**이다: 폭계열 6속성만 소유(4,428 노드)되고 height/min-height/이미지 높이/inset/padding/aspect-ratio/transform은 모든 컴포넌트에서 1440/390 px로 동결되어 h축 추적률이 0%다. 그 위에 두 개의 구조적 결함이 노드 간 분열을 만든다: (1) 관찰기가 DOM을 한 번 walk한 핸들을 폭 스윕 내내 재사용해 899/900 리마운트 서브트리 973 노드(데스크톱 가시 노드의 16–50%)가 probe 0으로 제안조차 되지 않고, (2) 검증기가 동결 baseline 위 단독 렌더와 1440 4px truth gate로 노드를 독립 판정하므로 콘텐츠 크기 노드가 폰트 편차(12.9–18.1px)로 거부되고, 그 동결 자식 하나의 min-content가 정확히 소유된 부모의 50/50 분배를 모든 폭에서 무너뜨린다(실험으로 증명). Hero는 컨테이너 토큰의 `height` 동결 + `aspect-ratio` 결합이 폭을 1439.97로 역산하는 CSS 원인, Swiper 슬라이드 폭 JS 원인, transform 시간 상태, 슬라이드 내부 관찰 사각의 4중 원인이다. 소스는 authored breakpoint 없이 flex/%/vw 비율만으로 일관성을 얻으므로, 클론의 중간 폭 파손은 누락된 breakpoint가 아니라 끊긴 비율 관계다. P0는 방출 기반으로는 CORRECT FOUNDATION이지만 수락 모델로는 WRONG FOUNDATION이며(MIXED), 권고는 관찰기 수정 → authored 번역을 기본값으로 하는 서브트리 원자 수락 → JS 값 measured fallback의 하이브리드(옵션 D)다. 신뢰도는 핵심 결론 전부 HIGH, 개별 노드의 거부 사유만 MEDIUM-HIGH(노드별 로그 미저장).
