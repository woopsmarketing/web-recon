## Root Cause — 한 개의 관측 사각지대

세 mismatch와 not-declared 5건 전부가 **같은 generic 관측 사각지대**로
수렴한다는 것을 live probe로 확정했다 (explorer의 baseline/diff 로직을 그대로
재현하는 read-only 스크립트로 세 시나리오를 stripe.com에서 측정):

1. **Framework portal은 0×0 wrapper 뒤에 숨는다.** locale listbox
   (`#:R5b9r6l6:` 1264×669, 665 elements), bento dialog (`#:R1mapr6l6H2:`
   1184×2628, 766 elements), mobile menu (`nav#:r4:` 390×778)는 전부
   클릭 시 body 레벨에 mount되는 컨테이너(`div#:r2:`/`#:r4:`, **1440×0 /
   390×0**) 안에 있다. 자식이 전부 `position: fixed/absolute`라 wrapper의
   rect가 0이고, Task 17 discovery는 mounted ROOT의 visibility만 검사했으므로
   overlay 전체가 후보조차 되지 못했다.
2. **`aria-controls`는 클릭 후에야 붙는다.** 세 케이스 모두 trigger가 열린
   뒤에만 `aria-controls=":r…:"`를 갖는다. Task 17의 declared-relation 처리는
   이미 후보인 element에 evidence를 붙이는 것만 했고, 선언된 element를
   후보로 **추가**하지는 않았다.
3. ip000003의 Task 17 discovered target 5개는 dialog가 아니라 **동시에
   lazy-mount된 페이지 그래픽**(candidateCount 37 중 면적 상위 5)이었다.
   진짜 dialog는 (1) 때문에 후보가 아니었고, 5개 조각은 after-DOM 좌표의
   structural path라 static tree에 resolve되지 못해 trigger 옆 in-flow로
   쌓였다 — clone 화면의 "흘러내린 콘텐츠"가 그것이다.
4. ip000005의 "reveal 후 height 0" (dt000002): static exact style token이
   닫힌 상태의 computed `height: 0px`를 그대로 고정하는데 (`.wr-st006266`),
   mount-kind target에는 open-state graft가 없어 자식을 mount해도 영역이
   자라지 못했다.
5. ip000006/ip000010의 trigger mismatch: nav host가 content-replaced로
   관측되었고 clone runtime이 `replaceChildren()`으로 nav를 교체하면서
   **live trigger 자신을 DOM에서 제거**했다 (clone triggerAfter가 빈 값인
   이유). 원본은 trigger를 유지한 채 aria-expanded를 뒤집는다 — source drift
   아님, clone defect. live 재방문에서도 방향은 false→true로 동일했다.
6. ip000003의 content fingerprint 순서 차이("A$72.00 /year" vs
   "/yearA$72.00"): capture가 element의 direct text를 위치 정보 없이 모아
   template이 항상 **선행 text node**로 붙였기 때문.
7. (조사 중 추가 발견) **mounted template의 style token이 stylesheet에
   방출된 적이 없었다** — `usedStyleTokens`는 static page node에서만 채워지고
   template node는 클릭 후에만 존재하므로, Task 16 이래 모든 mounted region이
   무스타일로 렌더되고 있었다. fixed overlay가 in-flow 텍스트 기둥으로
   무너진 직접 원인.
8. (〃) 선언된 declared-dynamic mount는 captured root를 wrapper **안에**
   중복 렌더해 clone region이 원본보다 한 단계 깊었다 — fixture의
   `dynamic-target:children` mismatch가 Task 16부터 존재했던 이유.
9. (〃) bento dialog는 expanded capture에서도 **depth-cap(24)**에 걸려 622

## Generic Corrections

전부 generic — Stripe selector/class/route/px 조건 0:

1. **Portal descent** (`discover-targets.ts`) — visibility gate에 실패한
   mounted root는 bounded 깊이로 내려가 topmost visible mounted descendant를
   후보로 올린다 (`portal-descent` evidence).
2. **Declared-after-click 후보 추가** — 클릭 후 trigger가 선언한
   `aria-controls`/`popovertarget`/… element가 후보가 아니면서 실제로 변했으면
   (newly-mounted 또는 hidden→visible) declared 후보로 추가. 변화 없는 선언은
   기존대로 snapshot 채널에만 남는다.
3. **Containment dedupe** — 후보끼리 포함 관계면 outermost가 이기고 evidence가
   병합된다. fixed overlay 안의 `position: static/relative` 패널을 단독
   mount하면 위치 문맥이 사라지는 것을 구조적으로 방지.
4. **Mount-host 증거** (explorer → sitespec → runtime) — newly-mounted
   region의 가장 가까운 **baseline 조상**의 structural path를 baseline 좌표로
   기록(`mountHostPath/Tag/ChildIndex`) → compile에서 exact resolve
   (`mountHostNodeId`) → runtime이 그 host의 관측된 child 위치에 mount.
   host가 없을 때만 Task 17의 trigger-옆 fallback.
5. **Adaptive bounded capture** (§4A) — 기본 cap(300/12/20k)은 유지, truncation
   이 **기록된** capture만 확장 cap(1,200 / 48 / 80k)으로 1회 재시도
   (`CapturedSubtree.expanded`). depth 48은 실측(overlay 25+ 단계)에 의한
   값이고 element cap이 1차 경계다. capture 전용 element당 text cap 2,000
   chars — capture에는 rendered.html 회복 채널이 없어 200-char cap이 곧
   콘텐츠 삭제였다. 무제한 capture는 여전히 구조적으로 불가능.
6. **Mount-kind open-state root graft** (`compile-interactions.ts`) —
   existing-with-mounted-content / content-replaced의 resolved root에 closed
   static token ↔ capture root token의 차이 선언을 `openStyleOverrides`로
   방출 (기존 reveal graft와 같은 safe predicate·같은 `[data-wr-revealed]`
   gate). height는 **관측된 open 값**으로만 회복 — 임의 px 없음.
7. **Trigger-inside-target 보호** (compile + runtime + QA) — target이 자기
   trigger의 조상이면 compile이 `containsTrigger`로 표시하고 template을 싣지
   않으며 (`observed-target-contains-trigger`), runtime은 방어적으로
   `region.contains(trigger)`면 mount 거부. QA는 그 target의 content 비교를
   `trigger-inside-target-content-not-replayed`로 이름 붙여 제외하고
   existence/visibility는 계속 비교한다 — 숫자 세탁이 아닌 명시적 분류 (§8D).
8. **Text-segment interleaving** (capture 전용 `textSegments` →
   `dynamic-template.ts`) — direct text run의 element-child 위치를 기록하고
   template이 그 위치에 #text node를 배치. dom.json은 바이트 동일 (flag off).
9. **Template root = region** (runtime) — 단일 root capture는 wrapper 없이
   root 자체를 region으로 mount (관측된 tag/attr/style/child 수 그대로).
   declared dynamic mount(`wr-dyn-*`)의 이중 wrapper도 같은 원리로 제거.
10. **Template style token 방출** (`plan-reconstruction.ts`) — mounted
    template이 참조하는 style token을 `usedStyleTokens`에 합집합. Task 16
    이래 무스타일이던 mounted region 전부가 관측된 computed style로 렌더된다.
11. **Discovery-id region 식별** — mount region id가
    `wr-obs-<patternId>-<discoveryId>` (위치가 아니라 정체성). QA는 그 id를
    직접 찾고, declared-dynamic 중복 발견은 `wr-dyn-*` region으로 해석
    (구식 clone의 nth fallback 유지). declared-dynamic 중복 suppress 규칙도
    identity 기반으로 좁혀 (같은 html id일 때만) portal이 함께 지워지지 않게
    했다.
12. **Transport ceiling 분리** — `data-wr-obs`는 256KB
    (`MAX_OBSERVED_ANNOTATION_BYTES`), 초과 시 가장 큰 template부터 개별
    drop. capture 경계는 upstream cap이 지킨다.
13. **List marker 관측** — `list-style-type/position/image`를 STYLE_WHITELIST에
    추가 (li의 `display: list-item`이 UA 기본 불릿을 살리는 것을 §9 리뷰에서
    실측).

## Known Limitations

- **SVG internal paint** — 계획대로 미수정 (17.1 절대 금지 목록). 다중 사이트
  표본 수집 후 별도 Task.
- **열린 overlay의 wide-viewport 좌표** — 1440 관측값 고정 (1920: -240px,
  2048: -304px 좌측 offset; 내용·크기는 동일). 열린 상태의 다중 폭 관측이
  없는 한 inference 대상이 아니다.
- **Font materialization** — mobile 좁은 폭에서 텍스트 재개행으로 인한 누적
  세로 offset (media-entertainment 0.477의 지배 원인, source-variance로 분해
  증명). 명시적 non-goal.
- **trigger-inside-target content** — trigger를 품은 host의 내부 content
  swap은 재생하지 않는다 (명명된 limitation; trigger 생존이 우선).
- **asset-load-failure ×47** — 비재료화 non-goal의 가시적 표본 (transient
  CDN 거동 포함). mounted promo 이미지도 동일 계열.
- content fingerprint는 정확 일치 비교라 live data region은 재방문 간에도
  mismatch로 보고될 수 있다 (이번 run에서는 0건).
