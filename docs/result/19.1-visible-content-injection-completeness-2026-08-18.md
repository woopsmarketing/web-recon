## Painted Twin Model

Slot V2 v2 adds the binding surface **`paint-twin`**: an aria-hidden static-tree occurrence attached to an EXISTING logical slot. Design rules (spec §2/§4):

- aria-hidden subtrees are **not** reopened as editable — no new slots, no new default-content entries. A twin is only ever an *additional occurrence* of an already-slotted visible text.
- Extraction records aria-hidden text nodes in a separate `hiddenTexts` channel (never slot candidates); the compiler's twin pass (`twin-binding.ts`) decides co-binding purely from deterministic evidence.
- The applier treats `paint-twin` exactly like `static` (the node lives in the static tree), so applying a value rewrites both layers in the same server-side pass — they can never desynchronize again.

## Twin Co-binding

All evidence must hold simultaneously (no AI, no fuzzy similarity):

1. same page **and** same viewport;
2. **byte-equal** text (hidden run == the binding's `expectedValue`);
3. the duplicate sits under an `aria-hidden="true"` boundary, not inside svg/script/style;
4. close structural ancestry — nearest common ancestor ≤ 4 element hops from both owners;
5. observed geometry: the SiteSpec carries bounding boxes for **both** owners and either the boxes are **byte-identical** (covers the mobile variant where both layers are 0×0 — the construct simply isn't rendered there, and co-binding keeps it synchronized anyway) or their strict intersection covers ≥ 50% of the smaller box (a paint layer shares its twin's pixels; stacked-adjacent duplicates are refused);
6. unambiguous pairing — each hidden occurrence co-binds at most once, to the closest match.

Stripe results: 4 paint-twin bindings — `home.main.hero.headline` (desktop+mobile, twin owner `n000132`, identical boxes `208,255 916×61`) and `home.main.heading.accept-payments-offer-financial` (desktop `n000135` identical boxes, mobile via identical 0×0 boxes). The "Crypto" mockup duplicate was **refused** (far ancestry, no overlap — it is a decorative product-mockup string, not a paint layer; see Layout Safety for how QA now classifies it).

The stale-twin detector keeps its teeth: a co-bound (synchronized) twin passes; the smoke's unsynchronized fixture (non-overlapping boxes → never co-bound) still FAILS the page.

## SVG Text Observation

A new deterministic scanner (`svg-text.ts`) gives a *narrow* view into the opaque SVG markup — nothing but rendered character runs:

- a run = maximal character data directly inside `<text>`/`<tspan>`, indexed in document order **before** any filtering (addresses never move when filter rules evolve);
- excluded as non-candidates: runs under `aria-hidden="true"`, `display:none`/`visibility:hidden` (attribute or inline style), `<title>`/`<desc>`;
- runs inside `<defs>` are candidates **only** when an ancestor inside the defs carries an id referenced by `url(#id)` / `href="#id"` in the same markup — exactly the Stripe cutout-mask indirection; unreferenced defs text stays excluded;
- the SVG geometry tree is **not** promoted to SiteSpec nodes; occurrences carry only `{hostNodeId, svgTextIndex, svgTextPath, value}` (e.g. `svg>defs>mask>text`).

Stripe home: 1 candidate run per viewport — `"Sign in"` at index 0 inside host `n000053`.

## SVG Text Binding

New binding target **`svg-text`** (surface stays static/dynamic-template; address = host nodeId + `svgTextIndex`, guarded by `expectedValue`):

- **Co-binding first (§10):** an SVG run under the SAME anchor host whose decoded value byte-equals an existing DOM label segment joins that slot as an additional occurrence. Stripe: the pill anchor `a#n000052` holds both the DOM label (`span#n000054`, already slot `home.header.nav.sign-in.label`) and the SVG host — so the existing slot gained 2 svg-text bindings and **no new slot was created** (slot count stays exactly 9,529; bindings 24,512 → 24,518).
- Runs that cannot be co-bound become standalone page-scope `content.text` slots (`<page>.<section>.svg.<slug>` keys) — no new semantic role invented.
- **Mutation is compile/render-time string surgery** in the server-side applier: rescan the host markup, guard the addressed run against `expectedValue`, splice in the **entity-escaped** replacement. No client-side querySelector patching, no post-hydration mutation, no innerHTML injection — only character data between the run's existing tags can change, so `fill`/`stroke`/`gradient`/`mask`/geometry are structurally untouchable.

## Known Limitations

- **SVG fill / stroke / stop-color / gradient / mask paint is still not restorable or editable** (`svg-internal-paint-and-geometry-not-slotted`). Wrong SVG colors remain a known limitation and are out of scope by spec (§12); the svg-text applier makes them structurally unreachable rather than merely unvisited.
- Only *visible* SVG text runs are slotted (`svg-text-only-visible-runs-slotted`): aria-hidden / css-hidden / title / desc / unreferenced-defs runs stay excluded.
- Paint twins without box-overlap (or box-equality) evidence are not co-bound (`aria-hidden-twin-without-box-overlap-evidence-not-cobound`) — the stale-twin detector still guards them.
- Decorative aria-hidden mockup regions keep their default strings by design; when such a string equals a changed slot's default it is reported as a non-failing `stale-duplicate-text-remnant`.
- SVG text length safety has no geometric probe (an over-long value can outgrow its viewBox); guarded by `sourceCharacterCount` constraints, applied-value verification and the mandatory visual pass.
- Dynamic-template-embedded SVG text runs did not occur in the canary; the applier handles them generically but no real-site case has exercised that path.
